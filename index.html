Caso 01 · Acceso con certificado

Certificado válido → 200

Chrome presenta el certificado Cliente1 instalado en Windows. El API consulta Key Vault y autoriza el acceso sin contraseña.

Caso 02 · Sin certificado

Sin certificado → 401

Se llama a /api/sin-acceso, que siempre responde 401. Chrome cachea el certificado de Windows, así que una petición «sin certificado» real se demuestra con curl.exe (ver Comandos demo).

Caso 03 · Revocación

Certificado revocado → 401

El API consulta Key Vault en cada petición: si el certificado está deshabilitado, lo rechaza.

  1. Ejecuta REVOCAR en PowerShell y espera unos segundos.
  2. Pulsa «Llamar con cert revocado»: debe dar 401.
  3. Ejecuta RESTAURAR, espera y pulsa «Restaurar y verificar»: debe dar 200.
Revocar certificado
az keyvault certificate set-attributes --vault-name kv-pki-proyecto3 --name cliente-1 --enabled false
Restaurar certificado
az keyvault certificate set-attributes --vault-name kv-pki-proyecto3 --name cliente-1 --enabled true
Caso 04 · Multi-dispositivo

Acceso desde varios dispositivos

El acceso no depende de una PC concreta, sino de poseer un certificado válido emitido desde Key Vault.

  • Key Vault es la fuente central del certificado: ninguna PC es dueña única de la identidad.
  • El acceso a Key Vault se controla con RBAC: se agregan o quitan dispositivos sin tocar el API.
  • Si un dispositivo se pierde, se revoca su certificado y deja de entrar, sin afectar al resto.
